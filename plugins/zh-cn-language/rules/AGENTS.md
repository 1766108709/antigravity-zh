# 全局简体中文交互规则 (Simplified Chinese Language Policy)

除非用户明确要求使用其他语言，否则请始终使用**简体中文**与用户沟通，并确保所有面向用户展示的工具调用参数也使用简体中文：

## 1. 对话与解释
- 所有日常回复、技术方案、问题排查、代码讲解与总结均使用自然、准确的**简体中文**。

## 2. 交互式提问卡片 (`ask_question`)
- 调用 `ask_question` 向用户提问或确认需求时：
  - `question`（问题正文）必须使用**简体中文**。
  - `options`（所有候选选项）必须使用**简体中文**（注：若有推荐首选项，请保留系统 UI 识别所需的英文前缀 `(Recommended) `，其后紧跟中文描述，例如 `(Recommended) 采用默认配置`）。

## 3. 命令执行与授权提示 (`run_command`)
- 调用 `run_command` 执行终端命令时，展示在执行/授权许可卡片上的 `toolSummary`（任务简述）必须使用简短清晰的**简体中文**短语（例如：`检查 Git 状态`、`运行单元测试`、`安装项目依赖`），不要使用英文示例短语。
- 若同一命令需要以 `BypassSandbox: true` 重试，请保持该中文 `toolSummary` 与上一次完全一致。

## 4. 工件文档与审批摘要 (`Artifacts`)
- 创建或更新计划书、报告、排查记录等 Markdown 工件（Artifacts）时，文档正文、标题、图表标签以及用于审批卡片展示的 `ArtifactMetadata.Summary` 均必须使用**简体中文**撰写。

## 5. 子代理与任务标题
- 面向界面展示的子代理角色名称（如 `invoke_subagent` 的 `Role`）、工作流简述（`run_workflow` 的 `Description`）等可读标签，优先使用简洁的**简体中文**名称。

## 6. 保持原样的技术内容
- 源代码中的变量名、函数名、类名、文件路径、终端命令本身、CLI 参数标志、JSON 配置键名与枚举值，以及不宜强行意译的通用技术专有名词（如 Git、Docker、API、MCP、Token 等）保持英文原样。
